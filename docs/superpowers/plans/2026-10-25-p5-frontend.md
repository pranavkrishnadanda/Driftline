# P5 Frontend Implementation Plan (P5a shell + P5b features)

> **For agentic workers:** executed by parallel subagents, one per task, each in its own git worktree. Follow the Implementer protocol in `docs/superpowers/plans/2026-10-25-p3-retrieval-agent.md` (TDD; unexpected errors are reported after one fix attempt of at most 15 minutes; **no Co-Authored-By or AI attribution in commits**; never read `.env`).

**Goal:** a Next.js + TypeScript app that makes Driftline's behaviour visible. You can watch the agent think live, see versions and supersession over time, receive drift alerts as they happen, work a review queue, and read system stats.

**Architecture:**
- `frontend/` is a Next.js App Router app (TypeScript strict, Tailwind v4, shadcn/ui, TanStack Query).
- A typed API client is generated from the gateway's OpenAPI document (`openapi-typescript`), and the SSE event types come from `contracts/sse/*.json`.
- One `useEventStream` hook handles SSE with `Last-Event-ID` resume.
- UI libraries, one owner per concern (spec §9):

| Library | Owns |
|---|---|
| **Motion** (motion.dev) | all component animation: timeline node states, subagent branch expansion, claim ✓/✗, layout transitions, alert entry |
| **anime.js** | choreographed SVG: supersession-graph edge drawing, version-timeline scrubber, landing hero |
| **Bklit UI** | every `/stats` chart (installed through the `@bklit` shadcn registry) |
| **Kokonut UI** | Ask input, buttons, cards, text effects (installed through its shadcn registry) |

**Spec:** `docs/superpowers/specs/2026-10-25-driftline-design.md` §8 (API and SSE contract), §9 (frontend), §12 (testing; no `jest.mock`/`vi.mock`).

## Global Constraints

- **Latest stable versions of everything.** Before installing, check with `npm view <pkg> version` (and for each GitHub action, `gh api repos/<o>/<r>/releases/latest`). Record the resolved versions in your report. Never pin from memory.
- **Fetch current docs before writing UI code:** motion.dev, animejs.com, Bklit UI and Kokonut UI (use `llms.txt` where it exists). Don't rely on remembered APIs. Install the Bklit skill with `npx -y skills add bklit/bklit-ui --agent claude-code`.
- Add Kokonut and Bklit components **through their shadcn registries as source files**, never as hand-copied snippets.
- Every animation honours `prefers-reduced-motion`. Never run Motion and anime.js on the same element.
- **No mocks.** No `vi.mock`, `jest.mock`, MSW, or fake fetch:
  - unit and component tests (Vitest + Testing Library) test pure logic and components with real props;
  - SSE and hook tests run against a **real local SSE server** started in the test (`frontend/tests/support/sse-server.ts`, a tiny Node `http` server that replays a contract fixture);
  - E2E (Playwright) runs against the real backend stack (Compose with `DRIFTLINE_LLM_OFFLINE=true`, so it costs nothing).
- The package manager is `pnpm` (latest). Use Node LTS (latest) pinned in `frontend/.nvmrc` and `engines`.
- Accessibility: every interactive element is keyboard-reachable, and `@axe-core/playwright` reports no serious or critical issues on each view.
- The gateway URL comes from `NEXT_PUBLIC_DRIFTLINE_API` (default `http://localhost:8010`). Add CORS for `http://localhost:3000` in the gateway (P5a T0 owns that backend change and its test).

## Review Focus

1. **The SSE connection drops mid-answer.** The hook reconnects with `Last-Event-ID`, and the timeline shows no duplicated or missing tokens. Owner: P5a T2 (`useEventStream resumes without duplicates`).
2. **Events arrive faster than React renders** (token bursts). Tokens are batched per animation frame and never dropped. Owner: P5a T2.
3. **`prefers-reduced-motion: reduce`.** No Motion or anime.js animation runs, and the content stays complete. Owner: P5b T5 (Playwright `reducedMotion: 'reduce'`).
4. **The backend is down or returns 429.** The Ask view shows a retry state that honours `Retry-After`, with no unhandled promise rejections. Owner: P5a T3.
5. **An insufficient-evidence answer** shows the nearest sources and an explicit refusal, never an empty bubble. Owner: P5b T1.

## P5a: shell (it can start now; it only needs the SSE contract fixtures from P3)

### Wave A0 (1 agent): Task 0, scaffold
**Files:**
- `frontend/`: `create-next-app` (latest, App Router, TypeScript strict, Tailwind v4, ESLint), then `shadcn init`, TanStack Query, Vitest + Testing Library, Playwright, `@axe-core/playwright`, `openapi-typescript`.
- Install `motion`, `animejs`, the Kokonut UI registry and the Bklit registry (base components only).
- `frontend/.nvmrc`; `frontend/package.json` scripts `dev`, `build`, `lint`, `typecheck`, `test`, `test:e2e`, `gen:api`.
- Backend: CORS middleware in `backend/src/driftline/gateway/app.py` for `settings.cors_origins` (default `["http://localhost:3000"]`), with a test in `backend/tests/gateway/test_cors.py`.
- Modify `.github/workflows/ci.yml`: add a `frontend` job (pnpm install, lint, typecheck, test, build), using the latest action majors (`actions/setup-node`, `pnpm/action-setup`).

**Tests:**
- `frontend/tests/smoke.test.tsx`: the root layout renders the app name.
- The backend CORS test: the preflight from `localhost:3000` is allowed, and a random origin is not.

**Gate:** `pnpm lint && pnpm typecheck && pnpm test && pnpm build`, plus the backend suite. Commit `feat(p5a): Next.js frontend scaffold`.

### Wave A1 (2 agents in parallel)
**Task 1: typed API client.**
- `frontend/src/lib/api/` holds `schema.d.ts`, generated by `pnpm gen:api` from `http://localhost:8010/openapi.json`, or from a checked-in `contracts/openapi.json` that the backend test `backend/tests/gateway/test_openapi_snapshot.py` writes and verifies.
- `client.ts` is a fetch wrapper with typed `ask()`, `job()`, `watch()`, `timeline()`, `review()`, `resolve()` and `stats()`.
- `ApiError {status, retryAfter}`.
- Tests: the wrapper against the real local test server (`tests/support/api-server.ts`, a Node http server returning fixture JSON). They cover 429 with `Retry-After` parsing and the error mapping.

**Task 2: `useEventStream` hook.**
- `frontend/src/lib/sse/` contains:
  - `parse.ts` (an SSE frame parser);
  - `events.ts` (TypeScript types generated from `contracts/sse/ask-events.v1.json` and `alert-events.v1.json` with `json-schema-to-typescript`);
  - `useEventStream.ts` (`fetch` plus a `ReadableStream` reader, `Last-Event-ID` resume with backoff, rAF batching of `token` events, and cleanup on unmount).
- Tests run against the real `tests/support/sse-server.ts`:
  - the parser handles split chunks, multi-line `data`, comments and heartbeats;
  - the hook resumes without duplicates after the server closes mid-stream;
  - a token burst of 5,000 events renders the full text;
  - unmounting aborts the request.

### Wave A2 (1 agent; needs T1's client and T2's hook)

**Task 3: app shell and the Ask view (no animation yet).**
- `frontend/src/app/(app)/layout.tsx` provides navigation for Ask, Timeline, Drift, Review and Stats.
- `frontend/src/app/(app)/ask/page.tsx` has the Kokonut AI input, an as-of date picker and a tenant select. It renders the streamed answer, claims, citations (hover shows the exact quote) and the `degraded` and `cached` badges.
- It handles 429 by honouring `Retry-After` and backend-down with a retry button.
- Tests:
  - component tests with real props built from the contract fixtures;
  - Playwright `ask.spec.ts` against Compose (offline LLM): ask a question about an uploaded fixture doc and assert the final answer and citations.

**Gate:** frontend lint, typecheck, test and build; Playwright ask spec; axe clean.

## P5b: features (needs P3 and P4 merged)

### Wave B1 (3 agents in parallel)
**Task 1: live agent timeline (Motion).**
- `frontend/src/components/agent-timeline/` lays out the graph nodes (classify, plan, subagents, merge, draft, verify, re_retrieve, respond) and animates them from `step` events. Subagent branches expand in parallel. Claims flip ✓/✗ from `claim` events. Layout transitions use Motion `layout`.
- The insufficient-evidence state shows a refusal plus the nearest sources.
- Tests:
  - a pure `timelineReducer(events) -> TimelineState`, unit-tested with fixture event sequences (fan-out, re-retrieve loop, error);
  - a component test;
  - a Playwright check that the nodes light up in order.

**Task 2: version timeline and supersession graph (anime.js + React Flow).**
- `frontend/src/app/(app)/documents/[id]/page.tsx` shows the versions on a time axis, with an anime.js scrubber, a side-by-side section diff, and a React Flow supersession graph whose edges are drawn with anime.js. Data comes from `GET /v1/documents/{id}/timeline`.
- Tests:
  - a pure `layoutTimeline(versions)` unit test (proportional positions, open-ended current version);
  - a Playwright check that scrubbing selects a version and updates the diff.

**Task 3: drift inbox and review queue.**
- `frontend/src/app/(app)/drift/page.tsx` shows live alerts from `/v1/alerts/stream`. Alert entry uses Motion. Each alert shows its before/after diff and verdict, with "accept" and "send to review" actions.
- `frontend/src/app/(app)/review/page.tsx` lists items by kind with approve/edit/reject. A 409 shows "already resolved".
- Tests: reducer and unit tests, plus Playwright `drift.spec.ts`: watch an answer, ingest v2 through the backend CLI inside the test (`docker compose exec`), the alert appears live, then resolve it.

### Wave B2 (2 agents in parallel)
**Task 4: `/stats` (Bklit UI).**
- Needs the backend `GET /v1/stats`, owned by this task as `backend/src/driftline/gateway/stats.py` plus a test. It returns:
  - corpus size (documents, versions, chunks);
  - drift events per day;
  - p50 and p95 ask latency from `jobs`;
  - cost per answer from `llm_calls`;
  - cache hit rate;
  - the latest `eval_runs` metrics.
- The frontend shows Bklit charts for every metric, using only the `@bklit` registry components.
- Tests: the backend endpoint against seeded real data; frontend formatting functions; a Playwright render check.

**Task 5: landing hero, polish and accessibility.**
- The `frontend/src/app/page.tsx` landing hero uses an anime.js choreographed SVG of a document "drifting" between versions, with Kokonut text effects.
- Playwright `a11y.spec.ts` runs axe on every view.
- `reduced-motion.spec.ts` (with `reducedMotion: 'reduce'`) asserts all content is visible with no animation running.
- Lighthouse runs in CI as a report only.

**Final P5 gate:**
- frontend lint, typecheck, unit tests, build, and all Playwright specs against Compose (offline LLM);
- the backend suite;
- the no-mock grep extended to the frontend (`grep -rnE "vi\.mock|jest\.mock|msw" frontend/src frontend/tests` prints nothing);
- no AI attribution in commits;
- push, and CI is green;
- screenshots of each view saved to `docs/screenshots/` for the README.
